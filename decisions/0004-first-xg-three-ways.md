# 0004. 最初の xG は距離と角度のロジスティック回帰にし、numpy・scikit-learn・statsmodels の 3通りで作って比べる

- Status: Accepted
- Date: 2026-11-08

## Context
シュートの表（decisions/0002・0003）から、最初の xG を作る。決める必要があったのは次のこと。

- 位置は縦横を 0〜100 にした割合なので、距離と角度を出すにはメートルにする必要がある
- 自陣（x<50）から打った普通のシュートが 100本・ゴール 4本ある。うち 3本はクロスからのヘディング（x=8）やこぼれ球（x=1）で、相手のゴール前のプレーが逆向きに記録されたと推定した
- 学習とテストの分け方と、当たり方の物差し
- ロジスティック回帰を何で作るか（numpy で自分で書く・scikit-learn・statsmodels）。それぞれに良さがあり、1つに決めずに比べることにした（2026-11-08）

## Decision
- 位置: ピッチを 105m×68m、ゴールの幅を 7.32m と置き、ゴールの中央（x=100, y=50）までの距離と、両ポストを見込む角度を特徴にする。特徴の組は「距離・角度」と「距離・角度・頭か体か」の 2つ
- 使うシュート: 普通のシュート（`shot_type` が `shot`）だけ。自陣（x<50）からの 100本は外す。表はそのまま
- 分け方: 試合単位で学習とテストを 8:2 に分ける（同じ試合のシュートは同じ側。乱数の種は 2026）
- 物差し: ログ損失・ブライアスコア・AUC・確率の当たり具合（テストを確率の低い順に 10等分）。いつも学習の平均の率を出すだけのモデルと並べる。物差しは numpy で書き、scikit-learn の関数と同じ値になるかをテストで確かめる
- 作り方: 同じ特徴・同じ分け方・同じ物差しで 3通り作り、係数・テストの確率・物差し・学習の時間を並べる（`mise run xg`）
  - numpy: ニュートン法を自分で書く（正則化なし）
  - scikit-learn: `LogisticRegression(C=np.inf)` で正則化を外す（`penalty=None` は 1.8 で非推奨になり、1.10 で消える）
  - statsmodels: `Logit`（係数の標準誤差・95% 信頼区間・p 値も出す）
- scikit-learn と statsmodels は型の情報がないので、呼ぶところを `libraries.py` にまとめ、pyright の strict の「型がわからない」の指摘はそのファイルとテストでだけ外す

## Consequences
- 3通りの係数は一致した。numpy と statsmodels は差が 1e-15 ほど（どちらもニュートン法）、scikit-learn は 2e-5 ほど（lbfgs の止め方の違い）で、テストの確率の差は最大 1e-5。物差しは 3通りとも同じ。自前の実装が正しいことの確かめになった
- 平均の率だけのモデルより、ログ損失 0.334 → 0.282（距離・角度）→ 0.277（頭か体かを足す）、AUC 0.50 → 0.78 → 0.79 によくなった。数字と読み方は `notes/xg-baseline.md`
- 使い分けの見込み: 仕組みの確かめと学ぶのは numpy、係数の意味を読むのは statsmodels（信頼区間・p 値）、次の交差検証や前処理のつなぎは scikit-learn（試合単位の分け方の道具がある）
- 依存に numpy・scikit-learn・statsmodels が増えた
- 作りながら見つけた不具合: 角度を `np.mod(角度, π)` で 0〜π に収めようとして、ゴールライン上（x=100）のポストの間の π を 0 にしていた。テストで見つけて直した（該当は 7本・ゴール 4本）
- 選ばなかった案: 1つの作り方に決める（3通りの答え合わせができない）、自陣のシュートを向きを戻して使う（逆向きかどうかを 1本ずつ確かめられない）、試合を見ずにシュートで分ける（同じ試合のシュートが両側に入り、当たり方がよく見える）
