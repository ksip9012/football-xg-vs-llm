# 0009. Claude は Opus 5.5 を Anthropic の API で呼び、テストから試合単位で選んだ 2,000本ほどで、Gemini と同じ説明・同じ情報で答えさせる

- Status: Accepted
- Date: 2026-11-15

## Context
decisions/0006 で、Gemini の本番のあと、Claude を少ない本数で足すと決めていた。「LLM は」と言える範囲が、Gemini 1つに限られないようにするため。決める必要があったのは、どこから呼ぶか、どのモデルか、何本・どの情報か、断られたときの扱い。

## Decision
- **呼び方**: Anthropic の API（`anthropic` の SDK、キーは手元の `mise.local.toml` の `ANTHROPIC_API_KEY`）。最初は Gemini と同じ GCP の Vertex AI で呼ぼうとしたが、このプロジェクトでは Claude の上限（quota）が 0 で、Opus・Sonnet・Haiku のどれも 429 になった（2026-11-15）。Anthropic が運営する Google Cloud の Claude は、準備（Marketplace の申し込み・新しい Anthropic の組織など）が多いので選ばなかった（2026-11-15 にユーザーが決めた）
- **モデル**: Claude Opus 5.5（`claude-opus-5-5`）。考えるのは止められないので、考える量をいちばん低い `low` にする（Gemini の LOW に合わせる）
- **シュート**: 最初の xG と同じテストのシュートから、試合を順番を混ぜて選び（種 2026）、2,000本以上になったところで止める。2,004本・90試合（ゴール 245本）。同じ試合のシュートはまとめて入るので、差の幅を試合単位で出せる
- **情報と送り方**: Gemini と同じ説明（`llm.system_prompt`）・同じ JSON・同じ 50本ずつ・同じ順番の混ぜ方。3つの情報と広い情報（decisions/0007）の両方。答えは構造化出力（`messages.parse` に `Predictions` を渡す）で受け取り、Gemini と同じく pydantic で確かめる
- **断られたとき**: `stop_reason` が `refusal` の回は答えなしとして記録し、最後にもう一度だけ送る。別のモデルへの切り替え（フォールバック）は入れない。別のモデルの答えが混ざると、Claude の比べにならないため
- **比べ方**: 同じ 2,004本で、統計モデル・Gemini・Claude の 6つ（2つの情報）を並べ、差の 95% の幅を試合単位のブートストラップで出す。高さを直したもの（decisions/0008。この 2,004本の中で試合単位の 5分割で学ぶ）も並べる

## Consequences
- 結果と読み方は `notes/llm-claude.md`
- 50本の 1回で、入力 2,695・出力 711 トークン（考えた分を含む）、$0.025・6.5秒だった。本番は 2つの情報で合わせて $2.21、答えなし・断り・形の崩れは 0
- 3つの情報では Claude と Gemini は見分けられず、広い情報では Claude のほうがよかった（ログ損失の差の幅 −0.0096〜−0.0004）。広い情報の Claude と統計モデルは見分けられない
- Gemini と同じテストの中のシュートなので、Gemini と Claude を同じシュートで比べられる。ただし本数が 4分の1 になるので、差の幅は広くなる
- 選ばなかった案
  - Vertex AI の上限を引き上げる申請をする（承認を待つ時間が読めない）
  - Sonnet 5.5・Haiku 5.5（安いが、「LLM の常識」の上のほうを見るには、大きいモデルがよい）
  - テストの全部（料金が 4倍）、1,000本（差の幅がさらに広がる）
  - 広い情報だけ（Gemini と同じ 4つの比べができない）
