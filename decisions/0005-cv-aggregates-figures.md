# 0005. xG は試合単位の交差検証で出して `shot_id, xg` の CSV に置き、選手・チーム・大会ごとに集計して、図は英語のラベルの PNG にする

- Status: Accepted
- Date: 2026-11-08

## Context
最初の xG（decisions/0004）で、選手・チーム・大会ごとに「xG の合計と実際のゴール」を比べたい。範囲は 2026-11-08 に、次の 3つに決めた。

1. モデルが信用できるかの図（確率の当たり具合・シュートの地図）
2. 選手・チーム・大会ごとの集計
3. 決定力が本物か（選手ごとの「ゴール − xG」が偶然ではないか）

あわせて、あとで LLM の予測を同じシュートに付けたとき、同じ集計・同じ図で並べられるようにしたい。決める必要があったのは、xG の出し方と置き方、集計の範囲、決定力の確かめ方、図の道具と文字。

## Decision
- **xG の出し方**: 試合単位の 5分割の交差検証（種 2026）。どのシュートの xG も、そのシュートの試合を学習に使っていないモデル（距離・角度・頭か体か、numpy のニュートン法）で出す。学習に使ったシュートで出すと、決定力の差が小さく見えるため
- **xG の置き方**: `shot_id, xg` の 2列の CSV（`data/xg_stat.csv`）。集計と図はこの形なら何でも受け取るので、LLM の予測も `data/xg_llm.csv` のように同じ形にすれば並べられる
- **集計の範囲**: モデルと同じ普通のシュート（PK・直接フリーキック・自陣を除く）。ゴールもこの範囲で数えるので、公式のゴール数とは合わない。表と図にそう書く
- **名前**: `players.json` の `shortName`・`teams.json` の `name` を pydantic のモデルで読む。元データの名前には `Bayern München` の形のエスケープが文字のまま残っているので、読むときに文字に戻す
- **決定力の確かめ方**: 大会ごとに試合を日付の順に並べて奇数と偶数に分け（前半と後半に分けると、移籍や調子の流れが混ざるため）、両方で 20本以上打った選手の「1本あたりのゴール − xG」の相関を見る。比べる相手として「1本あたりの xG（打つ場所のよさ）」の相関も並べる
- **図**: matplotlib の PNG を `notes/figures/` に置き、`mise run figures` で作り直す。ラベルは英語（matplotlib は既定で日本語を描けず、手元のフォントに頼ると CI やほかの PC で文字化けするため）。色は dataviz の既定のパレットの青 1色と、その濃淡だけ。図を作る処理は、作り物のデータで CI でも動かす
- 見せるための図（README に載せるもの）は、LLM との比べのあとに選ぶ

## Consequences
- 交差検証の xG の合計は 4,489.1、実際のゴールは 4,488（42,978本）。AUC は 0.779
- 決定力の相関は 0.138（95% の幅 0.004〜0.267、214人）、打つ場所のよさは 0.704（0.629〜0.766）。選手ごとの「ゴール − xG」の差は、あるとしても小さく、多くは偶然と読める（推定）。結果と読み方は `notes/xg-aggregates.md`
- 集計の CSV（`data/aggregates/*_stat.csv`）と図をリポジトリに入れた。作り直せば同じものができる（xG の CSV は sha1 まで同じだった）
- 依存に matplotlib が増えた。matplotlib は `**kwargs` の型を書いていないので、pyright の strict の「型が一部わからない」の指摘は `figures.py` だけで外した
- 選手 1人だけ `players.json` に名前がない（`(id …)` と出す）
- 選ばなかった案: 学習とテストを 1回だけ分けて、テストのシュートだけ集計する（選手ごとの本数が 2割に減る）、xG を表（`data/shots.csv`）の列に足す（LLM の予測と並べるときに表を作り直すことになる）、日本語のラベル（上の文字化け）、mplsoccer でピッチを描く（線を数本描くだけなので依存を増やさなかった）
- README に載せる図は、2026-11-15 に LLM との比べがひととおり終わってから選んだ。`shot_map.png`（モデルが場所ごとの決まりやすさを捉えているか）・`finishing_split_half.png`（決定力が続くか）・`llm_calibration.png`（Gemini は順位は同じで確率が低め）と、新しく作った `llm_summary.png`（LLM − 統計モデルの差と 95% の幅を 1枚にまとめたもの。色は dataviz の既定のパレットの 2番目と 3番目で、青は統計モデルに取っておいた）
- あとに回したもの: 状況ごと（直前のイベント・カウンター）、失点側（守備の xG）、試合ごとの xG と勝敗
