# 0003. 元データのイベントとシュートの表の 1行を pydantic のモデルにして確かめる

- Status: Accepted
- Date: 2026-11-08

## Context
シュートの表（decisions/0002）は、1行を `dataclass` で書き、元データのイベントは JSON の辞書を `int(...)`・`cast` で読んでいた。中身が期待どおりかは確かめておらず、項目が抜けると `KeyError` で落ち、型が違うと黙って変わる。モデルを作るときに CSV を読み戻すときも、型の決まりは notes の説明だけだった。

全イベント（7大会・3,251,294件）で数えると、項目はすべてのイベントにそろっていた。ただ、`eventSec` が整数のものが 24件、`subEventId` が空文字のものが 8,182件、位置が 1つのものが 741件あった。位置の値は全体では -1〜101、シュートの打った位置は 0〜100 だった。

## Decision
pydantic（v2）のモデルを 2つ置く（`src/football_xg_vs_llm/models.py`）。

- `Event`: 元データのイベント 1件。使う項目だけを持ち、名前は camelCase の別名で読む。ID などの型をそろえ、`subEventId` の空文字は「なし」にする。シュート以外のイベントも通るので、値の範囲は縛らない。zip の中の JSON は、`TypeAdapter(list[Event]).validate_json` でそのまま読む
- `Shot`: シュートの表の 1行。`shot_type`・`body_part`・`match_period`・大会は決まった値だけ、`x`・`y` は 0〜100、`event_sec` と `prev_seconds_before` は 0 以上、直前のイベントの 2列は両方あるか両方ないか。表を書くときと、`load_shots_csv` で CSV を読み戻すときの両方で使う

CSV の書き方（真偽は 0/1、値なしは空欄）は変えない。読み戻すときは、空欄を「なし」にする。

## Consequences
- 元データや表が決まりから外れると、作るときか読むときに、どの行のどの項目かがわかる形で止まる。CI でも、リポジトリの `data/shots.csv` を読み戻して確かめる
- 体の部位のタグがないシュートは、表に入れずに止まるようになった（今の元データでは、3種類とも全部に付いている）
- 元データにない大会の名前（新しい大会のファイル）が来ると止まる。足すときは `Competition` に書き足す
- 表を作る時間は 8.8秒から 18.6秒になった（全イベントをモデルで確かめる分）。作り直すのは元データが変わったときだけなので、許容する
- 依存に pydantic が増えた
- 選ばなかった案: シュートの行だけをモデルにする（元データの型の揺れは `int(...)` 頼みのまま）、DataFrame の列の型を pandera などで確かめる（元データを読むところは守れない）、`dataclass` のまま
